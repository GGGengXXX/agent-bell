1. 对于ssh远端机器上的进程，可以设置 ssh 反向隧道的方式，向本机器上的后台进程发起一个请求，然后本机有响应
2. 对于某一个终端上的进程，它在结束的时候可以调用这一个 hook ，然后它在结束的时候可以发起一个请求，然后本机有响应
3. 对于codex的一次执行，在结束的时候可以发起这样一个请求，然后本机上有响应；
4. 不论是本机还是ssh的机器，都可以做出响应

如何配置的需求：
用户需要足够的简单，即可完成配置，
对于某一个终端的进程，最后可以在终端命令前面加一个前缀，就可以在完成的时候触发提醒
对于codex，应该可以提供一键配置，codex原生的notify 已经有了 hook，我们可以利用原生的hook来达成我们的需求；
